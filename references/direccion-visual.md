# Dirección visual que explica

## Antes de maquetar

Escribir por slide: "El lector entiende ___ al ver ___". Completar el segundo espacio con contenido observable: filas de un presupuesto, una comparación, una conversación ilustrativa, una fotografía con acción, un documento anotado. Si solo aparece "ícono + textura", falta decidir cómo se explica la idea.

Elegir una familia visual apropiada a la marca y tema. Referencias se descomponen en criterios (escala, jerarquía, material, composición, luz, ritmo), sin copiar contenido ni identidad ajena.

Si la dirección ya está aprobada, continuarla. Si faltan referencias, formular una dirección con razones y producir portada + slide difícil para verificar internamente antes del lote. No imponer tres propuestas ni nuevas aprobaciones si el usuario ya pidió producir.

## Gramáticas que pueden alternarse

| Necesidad narrativa | Composición útil | Contenido que la hace funcionar |
| --- | --- | --- |
| Mostrar operación | Documento o interfaz protagonista con anotación | Campos legibles, un caso y resultado coherente |
| Comparar | Dos estados alineados o matriz breve | Mismas unidades/base, diferencias relevantes |
| Explicar causa/proceso | Diagrama con nodos y conexiones | Entradas, acciones y salidas identificables |
| Evidenciar un dato | Cifra contextual o gráfico apropiado | Fuente, período, unidad y escala honesta |
| Mostrar experiencia | Foto/ilustración con escena | Sujeto, acción y contexto ligados al copy |
| Fijar una idea | Composición tipográfica/editorial | Frase específica y ritmo de lectura |
| Invitar a actuar | Cierre de campaña | Beneficio real, acción y destino claros |

Alternar gramáticas entre slides cuando el relato lo pida. No fusionar todos los recursos en una lámina ni exigir un patrón A/B matemático. Una serie conserva identidad mediante tokens, voz y tratamiento, con variedad de composición y contenido.

## Espacio, tipografía y detalle

- Texto y gráfico son una unidad compositiva: flujo normal con gap explícito; no pegarlos a extremos opuestos de un lienzo
- Evaluar el hueco entre contenido visible, no entre cajas CSS. Ampliar la información útil cuando haya lugar; una tarjeta más alta con filas minúsculas no mejora legibilidad
- Jerarquía por escala, peso, contraste, posición y alineación. No resaltar todas las palabras ni hacer todo mayúsculas
- Revisar el tamaño efectivo en móvil: 30 px en fuente de 1080 se ven a 10 px en una muestra de 360. Ajustar según la lectura real, no por cumplir un mínimo teórico
- Referencia inicial, no cuota: a 1080 de ancho suelen funcionar títulos 64-100 px, cuerpo 34-44 px y ejemplos 30-36 px. Nombre de fuente, longitud y contenido pueden exigir otra escala
- Reducir redundancia, reorganizar o dividir antes de comprimir la fuente. No ocultar overflow para esconder errores
- Alinear ópticamente logo/glifos y revisar transparencia real, incluso en SVG
- Ejemplos con menor contraste o etiqueta "Ejemplo ilustrativo", conservando lectura. No meter toda la información en letra atenuada
- Texturas, recortes, iluminación y capas aportan materialidad al objeto. Variar su función, posición y escala; evitar el parche rectangular con bordes no intencionales
- Líneas de continuidad entre slides pueden guiar; cada imagen debe funcionar aislada. El mosaico del perfil depende de orden/crop y nunca justifica cortar información esencial

Sin cuotas de hexágonos, números héroe, fotos, gradientes, profundidad o área ocupada. No prohibir recursos solo porque una ejecución salió mal.

## Datos y diagramas

Elegir el gráfico a partir de la pregunta y datos disponibles. Una variación interanual negativa no es una serie: usar el porcentaje contextual o dos valores comparables, sin inventar trayectoria. No invertir sentido por estética.

Para conexiones, compartir coordenadas con los nodos (p. ej., SVG viewBox o anclajes calculados desde cajas reales). Verificar cada origen/destino, dirección y relación semántica. Un hub común puede contradecir un mensaje de soluciones personalizadas.

En gráficos comprobar escala, unidades, signo, orden, período, etiquetas y fuente. Una cifra suelta no necesita un gráfico de una sola barra. Datos ficticios deben tener relaciones aritméticas correctas y etiqueta.

## Assets y herramientas

Conservar logos oficiales. Para producto/UI/casos, usar evidencia autorizada o ejemplos declarados. Generación de imágenes sirve para escenas y metáforas; el texto largo, cifras y logos se componen después cuando requieren fidelidad. Revisar anatomía, artefactos, contexto y coherencia de luz.

Elegir una guía visual principal; pedir una segunda crítica solo para un problema concreto. De frontend se adoptan jerarquía y composición, no su framework, fuentes favoritas, hover o layout web por defecto. La marca prevalece sobre recomendaciones estéticas generales.
