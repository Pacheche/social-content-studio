# Observable review and delivery

## Review at three scales

For each final PNG: open it enlarged, then at 360-430 px of phone-equivalent width. Then review the set. The thumbnail grid detects monotony, but it does not replace reading each row and following each connection.

Evaluate: comprehension without extra explanation; copy and CTA; sign/base/unit of charts; fonts; real logo on background; hierarchy and order; legible examples; occlusions/edges; space between copy and asset; proportions; correct navigation. Ask "what does someone who did not read the brief understand?" and check it in the artifact.

Classify findings:
- Blocking: wrong format, unresolved claim, wrong data, missing assets, covered/illegible text, false connections, promised CTA that does not exist
- Quality adjustments: hierarchy, spacing, repetition, image artifacts, contrast, useful density
- Preferences: style variants that already meet the criteria. Do not impose unlimited touch-ups

Fix what was observed in one grouped pass and confirm the affected files. If failures persist, resolve them. When none remain, stop polishing.

## Review evidence

Keep the record in the sources, never among the images to upload:

| File + SHA-256 | Enlarged | Mobile | Facts/chart | Layout/logo/copy | Fix and recheck |
| --- | --- | --- | --- | --- | --- |
| Fill in when inspecting | Pending | Pending | Pending | Pending | Pending |

Add a sequence observation: variety with identity, continuity, navigation and closing. Do not fill in "OK" before opening. If shared CSS changes, review each affected file. A new hash invalidates the earlier approval of that export.

The technical auditor always returns a pending visual status. If there is no capability to view the files, deliver as a draft with that limitation, not as visually reviewed production.

## Learn from a correction

| Failure | Control that changes the next run |
| --- | --- |
| Large gap between text and chart | One block in flow, and measure visible content. No independent extremes |
| Small text with available space | Expand useful information and check mobile, not the frame |
| Rising chart for a year-over-year drop | Choose the representation from the data. Do not invent a series |
| Lines without a destination | Shared coordinates and a visual walk of each link |
| Decoration without content | Write the visual conclusion + example before drawing |
| All slides look the same | Change grammar/scale/material with a narrative function |
| Logo with background | Inspect the asset on the final background. Do not trust the SVG/PNG |
| Crop on publish | Confirm ratio and exact export against the real route |
| A technique with a minimum was applied without checking it | Measure the result against the threshold (anchor size, contrast ratio, text width) after applying it |
| Empty frame with a normal file size | A mis-computed `clipPath` or SVG geometry outside the viewport renders blank without errors; size checks miss it, opening the render does. Prefer simple shapes placed directly |
| False QA because render succeeded | Individual evidence and hashes. Review semantics separately |

## Closing

Deliver finals in order, a caption per channel, identified auxiliary assets and the editable source. Report what was reviewed and the real pending items. A local piece that is ready is not published. Do not use a beauty metric or an invented virality rate as proof of quality.
